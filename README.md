
## ПЗ №2: отдельный PostgreSQL в Docker

Ветка `pz22` использует независимую базу `microblog_pz22` на
`127.0.0.1:5433`. Таблицы создаются существующими миграциями ПЗ №1 и новой
миграцией комментариев. Данные облачной базы автоматически не копируются.

```sh
cp -n .env.pz22.example .env.pz22
# Заполните пароль, тот же пароль в DATABASE_URL и JWT_SECRET.
docker compose --env-file .env.pz22 -f compose.pz22.yml up -d --wait
npm run db:migrate:pz22
npm run db:status:pz22
npm run dev:pz22
```

В `.env.pz22` задан `NODE_ENV=pz22`: Sequelize выбирает локальную
конфигурацию без SSL. Команды явно загружают этот файл; обычный `.env`
с облачным подключением менять не нужно. Если порт приложения 3000 уже занят
лабораторным окружением, предварительно остановите его backend.

Таблицы: `Users`, `Tweets`, `LoginLogs`, `RequestLogs`, `Comments`.
Служебная `SequelizeMeta` хранит список выполненных миграций.
Комментарий содержит текст, ID автора и ID поста. Внешние ключи запрещают
ссылки на несуществующие записи. Удаление поста удаляет его комментарии;
удаление автора комментариев запрещено до удаления или переназначения комментариев.

Для подключения из pgAdmin, работающего на компьютере:
хост `127.0.0.1`, порт `5433`, база и пользователь из `.env.pz22`.
Если сам pgAdmin находится в Docker Desktop, адрес хоста —
`host.docker.internal`, порт остаётся `5433`.

```sh
docker compose --env-file .env.pz22 -f compose.pz22.yml down
```

При остановке без `-v` данные остаются в отдельном томе `pz22_pgdata`.
Пароль и имя базы в файле окружения применяются при первой инициализации
пустого тома: их изменение не меняет уже существующие учётные данные.

 
### REST API ПЗ №2

Маршруты новых ресурсов: /api/users, /api/tweets, /api/comments.
Документация и примеры: API.md. Swagger доступен на /api-docs,
объединённая спецификация — на /openapi.json.
Коллекция для Postman: postman/pz22.postman_collection.json.

Проверка на отдельной локальной базе:
 
~~~sh
npm run test:pz22
~~~

Тесты проверяют CRUD, различие PUT/PATCH, права, фильтры, каскадное удаление,
валидацию и совместимость с прежним входом через /auth/login. Тестовые
пользователи и посты удаляются после проверки; записи журнала запросов остаются.

### Веб-интерфейс

Откройте /: без JWT интерфейс перенаправит на /login. На одном экране
можно переключаться между входом и регистрацией. После входа открывается
лента; комментарии доступны по ссылке в посте. auth=1 больше не имитирует
вход. Токен хранится в sessionStorage и удаляется кнопкой «Выйти».
Права на запись всегда проверяет API, а не только кнопки интерфейса.
