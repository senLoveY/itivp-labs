# Микроблог (ИТиВП, лабораторные работы)

Сервер: Node.js + Express + PostgreSQL (Sequelize), аутентификация JWT.
Комментарии к твитам хранятся в MongoDB (Mongoose) – лабораторная работа №6.
Обновления в реальном времени через Socket.IO – лабораторная работа №7.
Клиент: React + Vite (папка `client`).

## Запуск сервера

```
npm install
```

Создать файл `.env` по образцу `.env.example`:

```
DATABASE_URL=строка подключения к PostgreSQL
JWT_SECRET=любой секретный ключ
MONGO_URI=строка подключения к MongoDB
```

### Подключение MongoDB Atlas

1. Создать бесплатный кластер (M0) на [MongoDB Atlas](https://cloud.mongodb.com).
2. В разделе **Database Users** создать пользователя с ролью «Read and write to any database».
3. В разделе **Network Access** добавить свой IP (или `0.0.0.0/0` для учебного проекта).
4. Скопировать строку подключения (**Connect → Drivers**), подставить логин, пароль и имя базы:

```
MONGO_URI=mongodb+srv://<user>:<password>@<cluster>.mongodb.net/microblog_mdb?retryWrites=true&w=majority&authSource=admin
```

Параметр `authSource=admin` нужен, если DNS не отдаёт TXT-запись кластера – без него подключение
падает с ошибкой `bad auth : Authentication failed`. Вместо Atlas можно использовать локальный MongoDB:
`MONGO_URI=mongodb://localhost:27017/microblog_mdb`.

Коллекции `comments`, `notifications` и индексы создаются автоматически при первом запуске,
миграции для MongoDB не нужны.

Применить миграции и (по желанию) заполнить базу тестовыми твитами:

```
npx sequelize-cli db:migrate
npx sequelize-cli db:seed:all
```

Запустить:

```
npm run dev
```

Сервер работает на http://localhost:3000, документация API – http://localhost:3000/api-docs.
Socket.IO работает на том же порту.
При успешном подключении в консоли появится `MongoDB connected`.

## API комментариев (MongoDB)

Комментарий хранится одним документом: ссылка на твит из PostgreSQL (`tweetId`), текст, лайки
и вложенные массивы `replies` (ответы), `editHistory` (история правок), `likedBy`.

| Метод | Путь | Описание |
|---|---|---|
| GET | `/comments?tweetId=` | список комментариев |
| GET | `/comments/:id` | комментарий по id |
| POST | `/comments` | создать комментарий (`tweetId`, `text`) |
| PUT | `/comments/:id` | изменить текст, старый сохраняется в `editHistory` |
| DELETE | `/comments/:id` | удалить, в ответе возвращается удалённый документ |
| PATCH | `/comments/:id/like` | поставить / снять лайк |
| POST | `/comments/:id/replies` | добавить ответ (`$push`) |
| PUT | `/comments/:id/replies/:replyId` | изменить текст ответа (`$set` элемента массива) |
| PATCH | `/comments/:id/replies/:replyId/like` | лайк ответа (`$inc` элемента массива) |
| DELETE | `/comments/:id/replies/:replyId` | удалить ответ (`$pull`) |
| GET | `/comments/stats` | топ твитов по комментариям (aggregation pipeline) |
| GET | `/comments/counts?tweetIds=1,2` | количество комментариев для нескольких твитов |

Изменение и удаление доступно автору или администратору. При удалении твита его комментарии
удаляются из MongoDB каскадно.

## API уведомлений (MongoDB)

| Метод | Путь | Описание |
|---|---|---|
| GET | `/notifications` | последние 20 уведомлений и число непрочитанных |
| PATCH | `/notifications/read` | отметить все уведомления прочитанными |

Уведомления старше 30 дней MongoDB удаляет сама (TTL-индекс по `createdAt`).

## Реальное время (Socket.IO)

Действия (пост, лайк, комментарий) выполняются через REST, после записи в базу сервер рассылает
событие через Socket.IO. Логика сокетов – в папке `socket/`, на клиенте – `client/src/socket.js`.

Подключиться может только авторизованный пользователь: клиент передаёт JWT при подключении,

```js
io(VITE_API_URL, { auth: { token } })
```

сервер проверяет его в `io.use()`. С неверным токеном соединение отклоняется (`connect_error`),
клиент выходит из аккаунта.

**Комнаты**

| Комната | Кто в ней | Что туда приходит |
|---|---|---|
| `user:<email>` | все вкладки пользователя | личные уведомления |
| `tweet:<id>` | у кого открыты комментарии поста | изменения комментариев, «печатает…» |

**События от сервера**

| Событие | Кому | Данные |
|---|---|---|
| `users:online` | подключившемуся | список email пользователей в сети |
| `user:online` / `user:offline` | всем, кроме него / всем | email |
| `tweet:new`, `tweet:update` | всем | твит |
| `tweet:delete` | всем | `{ id }` |
| `tweet:like` | всем | `{ id, likesCount }` |
| `comment:count` | всем | `{ tweetId, count }` |
| `comment:upsert` | комнате поста | комментарий целиком |
| `comment:delete` | комнате поста | `{ id, tweetId }` |
| `comment:typing` | комнате поста, кроме печатающего | `{ tweetId, email, typing }` |
| `notification` | личной комнате | уведомление |
| `notifications:read` | личной комнате | – |

**События от клиента**

| Событие | Данные | Ответ (acknowledgement) |
|---|---|---|
| `tweet:join` | `tweetId` | `{ ok: true }` или `{ ok: false, error }` |
| `tweet:leave` | `tweetId` | – |
| `comment:typing` | `{ tweetId, typing }` | – |

**Проверка в двух окнах.** Открыть клиент в обычном окне и в окне инкогнито (у них разный
`localStorage`), войти под разными пользователями. В первом окне появится «… в сети» и «Онлайн: 2».
Новые посты другого пользователя появляются плашкой «Новые посты», лайки и счётчики комментариев
обновляются сразу, в открытых комментариях видно «… печатает…», а лайк, комментарий или ответ
приходит уведомлением в колокольчик. Если остановить сервер, появится «Нет соединения с сервером»,
после запуска клиент переподключится сам.

## Интерфейс

Слева боковая панель: разделы (Лента, Мои посты, Статистика, Админка), уведомления,
число пользователей в сети и профиль с кнопкой выхода. Над лентой поиск по твитам.

- **Новый пост** – строка «Что нового?» над лентой открывает окно, где вводится текст и теги.
- **Комментарии в ленте** – под постом показываются 3 последних комментария и до 2 ответов к каждому,
  ниже ссылка «Все комментарии (N)».
- **Страница поста** – открывается кликом по тексту поста или по «Все комментарии»: пост и всё
  обсуждение, комментарии подгружаются по 20 при прокрутке. «Назад» возвращает в раздел, откуда открыт пост.

## Запуск клиента

```
cd client
npm install
```

Создать файл `client/.env` по образцу `client/.env.example`:

```
VITE_API_URL=http://localhost:3000
```

Запустить:

```
npm run dev
```

Открыть адрес, который покажет Vite (обычно http://localhost:5173).

## Вход

На странице входа нажать «Зарегистрироваться», ввести email и пароль.
Пароль: минимум 8 символов, заглавная и строчная буква, цифра и спецсимвол.
После регистрации вход выполняется автоматически.
