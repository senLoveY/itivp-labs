# API ПЗ №2

База: PostgreSQL microblog_pz22. Основной адрес: http://localhost:3000/api. Swagger: /api-docs. Полная спецификация: /openapi.json. Swagger содержит только 18 операций ПЗ №2 и POST /auth/login; прежние JSON-маршруты не дублируются в документации.

## Запуск
~~~sh
docker compose --env-file .env.pz22 -f compose.pz22.yml up -d --wait
npm run db:migrate:pz22
npm run dev:pz22
~~~

## Доступ и ошибки
Создание пользователя открыто: POST /api/users. Вход: POST /auth/login с email и password; поле token ответа передаётся в Authorization: Bearer <token>.
GET постов и комментариев открыт. Список пользователей доступен только администратору. Детали, обновление и удаление пользователя доступны ему самому и администратору. Запись постов и комментариев разрешена автору и администратору. Роль и блокировка проверяются по БД. Роль нового пользователя всегда user; хеш пароля в ответы не попадает.
PUT требует все изменяемые поля, PATCH — непустое подмножество. Неизвестные поля, включая роль, блокировку, даты и likesCount, отклоняются.
200 — чтение и изменение; 201 — создание с заголовком Location; 204 — удаление без тела.
400 — неверные данные, ID или JSON; 401 — отсутствующий/истёкший JWT; 403 — чужая запись или блокировка; 404 — нет записи; 409 — конфликт email или зависимостей; 500 — внутренняя ошибка.
Ошибка имеет вид {"error":"Описание"}. GET списка возвращает массив объектов, GET по ID/POST/PUT/PATCH — объект.

## Валидация и связи
Email: до 254 символов, корректный адрес, нормализуется в нижний регистр. Пароль: 8–72 символа, заглавная и строчная буква, цифра и один из @$!%*?&, остальные допустимые символы — латинские буквы и цифры.
Текст поста/комментария: 1–280 символов после trim. hashtags: до 10 строк по 40 символов без пробелов/запятых, нормализуются регистр, # и повторы.
Все ID — положительные целые числа. authorId и tweetId должны ссылаться на существующие записи.
Прежняя таблица Tweets хранит email в author. API преобразует входной authorId в email; смена email пользователя транзакционно обновляет его посты.
Удаление поста каскадно удаляет Comments. Пользователя с постами или комментариями удалить нельзя (409). При удалении пользователя без зависимостей удаляются его LoginLogs. RequestLogs остаётся техническим журналом.

## Таблица маршрутов

| Метод | Адрес | Назначение |
|---|---|---|
| GET | /api/users | список |
| GET | /api/users/:id | детали |
| POST | /api/users | создание |
| PUT | /api/users/:id | полная замена |
| PATCH | /api/users/:id | частичное изменение |
| DELETE | /api/users/:id | удаление |

## users
POST и PUT:
~~~json
{
  "email": "demo@example.com",
  "password": "DemoPass!9"
}
~~~
PATCH:
~~~json
{"email": "demo@example.com"}
~~~
Пример ответа POST (201), GET по ID/PUT/PATCH (200):
~~~json
{
  "id": 1,
  "email": "demo@example.com",
  "createdAt": "2026-11-20T12:00:00.000Z",
  "updatedAt": "2026-11-20T12:00:00.000Z",
  "role": "user",
  "isBanned": false
}
~~~
| GET | /api/tweets | список |
| GET | /api/tweets/:id | детали |
| POST | /api/tweets | создание |
| PUT | /api/tweets/:id | полная замена |
| PATCH | /api/tweets/:id | частичное изменение |
| DELETE | /api/tweets/:id | удаление |

## tweets
POST и PUT:
~~~json
{
  "content": "Первый пост",
  "hashtags": [
    "#rest"
  ],
  "authorId": 1
}
~~~
PATCH:
~~~json
{"content": "Первый пост"}
~~~
Пример ответа POST (201), GET по ID/PUT/PATCH (200):
~~~json
{
  "id": 1,
  "content": "Первый пост",
  "hashtags": [
    "#rest"
  ],
  "createdAt": "2026-11-20T12:00:00.000Z",
  "updatedAt": "2026-11-20T12:00:00.000Z",
  "author": "demo@example.com",
  "likesCount": 0
}
~~~
| GET | /api/comments | список |
| GET | /api/comments/:id | детали |
| POST | /api/comments | создание |
| PUT | /api/comments/:id | полная замена |
| PATCH | /api/comments/:id | частичное изменение |
| DELETE | /api/comments/:id | удаление |

## comments
POST и PUT:
~~~json
{
  "text": "Комментарий",
  "authorId": 1,
  "tweetId": 1
}
~~~
PATCH:
~~~json
{"text": "Комментарий"}
~~~
Пример ответа POST (201), GET по ID/PUT/PATCH (200):
~~~json
{
  "id": 1,
  "text": "Комментарий",
  "authorId": 1,
  "tweetId": 1,
  "createdAt": "2026-11-20T12:00:00.000Z",
  "updatedAt": "2026-11-20T12:00:00.000Z"
}
~~~

## Фильтрация
GET /api/tweets?authorId=1 — посты автора (404 при отсутствии автора).
GET /api/comments?tweetId=1&authorId=2 — комментарии с обоими фильтрами. Пустая выборка возвращает [].

## Postman
Импортируйте postman/pz22.postman_collection.json. Коллекция выполняется сверху вниз, создаёт уникального пользователя и тестовый пост с комментарием, получает токен и удаляет свои тестовые данные в конце. Список пользователей требует отдельного токена администратора.
